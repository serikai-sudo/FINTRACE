# FINTRACE design note

An engineer's tour of the mechanisms behind the claims. Every mechanism is named by module and
by the test that holds it in place; the test node ids are listed in
[`compliance_matrix.md`](compliance_matrix.md). The rules the code follows are in
[`CONTRIBUTING.md`](../CONTRIBUTING.md); the invariants quoted below are its §6.

## The problem in one paragraph

An audit agent must find the handful of real errors in a ledger (duplicate invoices, misallocated
or partial payments, wrong FX conversions, postings in the wrong period) without flagging the
look-alikes that are legitimate (recurring suppliers, split payments, refunds, similar invoices).
Training such an agent needs an environment whose ground truth is exact, whose reward cannot be
gamed, whose episodes can be regenerated byte for byte, and whose output speaks the language of
real audit tooling. FINTRACE is built around five pillars that map onto those needs.

## Pillar 1: Ground-truth integrity

*The hidden truth is exact by construction, not by annotation.*

- `src/fintrace/generator/` builds a clean double-entry history first (`build_clean_episode`),
  validated by `generator/validate.py` (balanced journals, invoice totals, payment allocations,
  ledger↔document links, period bounds). Only then do the injectors run. The first-digit
  distribution of the amounts is checked against Benford's law by chi-squared in the test suite
  (`tests/contract/test_generator.py::test_benford_passes_95_of_100_seeds`), not enforced by the
  generator.
- `generator/injectors/` holds one module per error type (`duplicate.py`, `payment.py`,
  `fx_error.py`, `period.py`) plus `interacting.py` for two-issue scenarios. Each injector returns
  the mutated episode, the `Issue` it created (type, canonical `affected_ids`,
  `expected_amount_minor`, currency, acceptable evidence sets) and a `ProvenanceEntry`
  (original and modified records). An **independent check** re-derives every issue from the
  public books after injection; if a later injection masks an earlier one, the build fails
  instead of shipping an unprovable truth.
- Decoys (`DecoyCounts`: repeated payment amounts, split payments, refunds, similar invoices) are
  part of the clean history, so a policy that flags every look-alike loses.
- Infeasible seeds are skipped and recorded (`data/manifest.json` lists the skipped seeds and the
  reason), never patched by hand.

Held by: the four `tests/contract/test_injector_*.py` files (including the 200-seed sweeps),
`tests/contract/test_interacting_scenarios.py`, `tests/contract/test_decoys.py`,
`tests/contract/test_validate.py`.

## Pillar 2: Isolation and leak-proof scoring

*The agent can only ever see what an auditor would see.*

- `PublicEpisode` and `PrivateEpisode` are separate Pydantic models (`src/fintrace/models.py`).
  The environment (`environment/env.py`) and every tool (`tools/`) hold a `PublicEpisode`; the
  truth goes into an evaluator-side `TruthStore` at reset and is read once, on the terminal step.
- The agent surface is minimal and fixed: five tools, observations validated against
  `ToolResult`, errors reduced to `{"error": {"code": "<CODE>"}}` (`environment/observations.py`),
  `info` limited to `{max_steps, version}`.
- An import firewall (`tests/contract/test_runner.py`) scans every module under
  `fintrace.agents` (the 20 attackers included) for imports of the evaluator, reward,
  environment or generator, for escape hatches (`importlib`, `sys`, `open`, private attributes)
  and re-checks in a fresh interpreter that importing the agents loads none of those packages.
- A leak scanner (`src/fintrace/logging/trajectory.py`: `forbidden_tokens`, `forbidden_keys`)
  runs over trajectories, over the OCEL export and, in the security tests, over every observation
  of randomised and real investigations, looking for truth vocabulary, provenance fields, issue
  ids, the seed and evaluator metrics.
- The jury adapter (`judge_adapter.py`) adds no scoring logic of its own, returns reward `0` to
  the policy in closed mode on every step, and uses static error messages.

Held by: `tests/security/` (isolation, full leak scan, trajectory, OCEL and adapter leak tests),
`tests/contract/test_runner.py`, `tests/contract/test_attack_isolation.py`,
`tests/contract/test_judge_adapter.py`.

## Pillar 3: Reproducibility and auditability

*Same seed, same config, same bytes.*

- All randomness flows from one `random.Random(seed)`; the generator derives per-injector
  sub-generators from the seed and config (`generator/build.py`), so adding an injection never
  reshuffles the base books. Ruff bans the global RNG, wall-clock calls and `uuid4`.
- Every artefact has one canonical serialisation: `exporters/episode_files.py` (canonical JSON,
  sorted CSV columns, LF line ends, `checksums.sha256` over the public files; `write_episode` and
  `read_episode` are exact inverses), `logging/trajectory.py` (one canonical JSON line per step),
  `exporters/ocel.py` (explicitly ordered collections).
- The committed dataset (`data/train`, `data/dev`: 10 + 10 episodes from disjoint seed ranges) is
  regenerated in the slow suite and compared byte for byte; `make data-verify` re-hashes it.
- Trajectories record every action with the agent's own `thought`, so an investigation can be
  replayed and reviewed step by step without a clock or a seed in the file.

Held by: `tests/repro/test_determinism.py`, `tests/repro/test_data_integration.py`,
`tests/repro/test_record_trajectories.py`, `tests/contract/test_trajectory_logger.py` (canonical
lines), the determinism tests of the oracle-gap and OCEL modules.

## Pillar 4: Adversarial robustness

*The reward holds against policies built to exploit it.*

- `evaluator/matcher.py` matches findings to issues one-to-one (maximum matching, so flooding
  and duplication cannot buy extra true positives), requires the right type and currency,
  canonical ids, an amount within `max(1, floor(0.001 × expected))` and an evidence superset of
  one acceptable set. `reward/official.py` is `clip(2·F1 − 1 − 0.002·steps, −1, 1)`: silence on
  erroneous books and false accusations on clean books both score −1, and every inspection step
  has a price.
- `agents/attacks/` holds 20 reward-hack policies, each probing one defence (flooding, empty or
  neighbouring evidence, tolerance edges, currency swaps, zero or astronomical amounts, wrong or
  misspelt types, look-alike ids, foreign episode ids, budget burning). `make attacks` runs them
  on the held-out dev split: all 20 are defeated (mean ≤ −0.3; best −0.782; 15 on the −1.000
  floor), and the report is regenerated and byte-compared in CI.
- `transforms/robustness.py` remaps ids, shuffles records and shifts time; rewards of the oracle
  and the rule-based baseline are invariant, so no policy can learn the generator's labelling.
- `diagnostics/oracle_gap.py` isolates one error type per episode and measures the gap between
  the oracle and every policy: the rule-based baseline is 4.1× further from the oracle on
  `payment_allocation` than on `duplicate_invoice`, while every attacker stays at the floor on
  every error type. The environment gives a gradient, not a pass/fail bit.

Held by: `tests/reward/` (matcher, adversarial matcher, metrics, reward, adversarial reward),
`tests/robustness/test_attackers.py`, `tests/integration/test_run_attacks.py`,
`tests/robustness/test_transforms.py`, `tests/contract/test_oracle_gap.py`.

## Pillar 5: Interoperability with audit tooling

*The jury harness, process-mining tools and an offline box all consume it as is.*

- `judge_adapter.py` implements the jury connection protocol (`generate_episode`, `make_env`,
  `score_episode`) as a translation layer over the existing environment and evaluator: closed
  mode loads an episode directory exactly as written, the 100-action and 60-second budgets are
  enforced by the environment itself, and `score_episode` returns the seven score fields.
- `exporters/ocel.py` exports an investigation as an OCEL 2.0 object-centric event log
  (invoices, payments, FX rates, the episode and the agent's findings as objects; tool calls as
  events), validated against `schemas/ocel.schema.json`, structurally checked and leak-scanned
  before it is written, so an auditor can open the trace in PM4Py or Celonis.
- The Docker image ships `src/` and `judge_adapter.py` on a digest-pinned `python:3.11-slim`
  base, runs as a non-root user and installs only `pydantic`, `pyyaml` and their support
  packages (six pins). `tests/integration/test_jury_protocol_offline.py` runs the complete protocol with every
  socket and name lookup blocked on every CI run; `make docker-verify` repeats it inside the
  container under `--network none --cpus 2 --memory 4g` wherever a daemon exists
  (`docker_offline_verification.md`).

Held by: `tests/contract/test_judge_adapter.py`, `tests/security/test_adapter_isolation.py`,
`tests/contract/test_ocel.py`, `tests/security/test_ocel_leak.py`,
`tests/integration/test_jury_protocol_offline.py`.

## Architectural invariants (CONTRIBUTING.md §6)

| Invariant | Mechanism | Held by |
|---|---|---|
| PublicEpisode vs PrivateEpisode: tools and the environment read the public half only; the evaluator alone reads truth and provenance | separate frozen models; `TruthStore`; `read_public_episode` for exporters | `tests/contract/test_models.py::test_public_episode_is_frozen`, `tests/integration/test_env_full_loop.py::test_full_loop_tools_cannot_import_evaluator` |
| `truth.json` and `provenance.json` never reach the agent surface | leak scanner over observations, trajectories and exports; static error messages | `tests/security/test_isolation.py::test_no_truth_in_observations_via_100_random_steps`, `tests/security/test_leak_scan_full.py::test_leak_scan_20_seeds_100_steps_each` |
| Evaluator isolation: `agents/*` never import `evaluator/*`, directly or transitively | AST + subprocess import firewall | `tests/contract/test_runner.py::test_oracle_not_accessible_from_agents`, `tests/contract/test_attack_isolation.py::test_no_evaluator_imports_in_attacks` |
| Error contract: every environment error is exactly `{"error": {"code"}}` | `Error` model with `extra="forbid"`; `build_error_result` drops messages | `tests/contract/test_models.py::test_error_is_code_only`, `tests/contract/test_env_fuzz.py::test_fuzz_action_envelopes_never_crash` |
| Determinism: same seed + config ⇒ byte-identical files and identical rewards | single seeded RNG, canonical serialisation, banned wall-clock APIs | `tests/repro/test_determinism.py::test_deterministic_regeneration`, `tests/repro/test_data_integration.py::test_generate_data_timing` |
| Budgets: ≤ 100 steps and ≤ 60 s per episode end the episode with a code, not an exception | `EpisodeState` step counter; `time.monotonic` deadline kept off-state | `tests/contract/test_env.py::test_truncation_at_100_steps`, `tests/contract/test_judge_adapter.py::test_60s_timeout_C18` |
| Versioning: `config/versions.json` and `schema_version` are the source of truth | `$id` of every schema derived from `SCHEMA_VERSION` | `tests/contract/test_schemas.py::test_schema_ids_follow_convention` |

## What is deliberately not here

- No learned model is shipped: the baselines are a random investigator, a rule-based auditor, a
  mark-everything attacker and a truth-reading oracle. The CPU behaviour-cloning proof
  (`experiments/bc_proof/`, torch pinned in its own requirements and venv) shows the expert's
  actions are learnable from public observations; it claims no rollout reward and never enters
  the image or the main test suite.
- No network, GPU or heavy dependency in the runtime path, by test rather than by promise.
- No hand-edited data: every committed episode, report, chart and log is the output of a `make`
  target and is regenerated and compared by the slow suite.
